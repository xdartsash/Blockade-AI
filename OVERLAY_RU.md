# Черновая разметка по цветным рамкам

Инструмент ищет тонкие замкнутые красные/зелёные прямоугольники. Проверяет четыре стороны, толщину, насыщенный цвет и пропорции. Флаг --require-stable требует совпадения на двух соседних кадрах. Это уменьшает ошибки на цветных стенах, но настоящая прямоугольная вывеска может пройти фильтр. Перекрывающиеся, обрезанные, слишком маленькие и повреждённые рамки могут быть пропущены.

На двух присланных вырезках найдены соответственно одна зелёная и одна красная рамка. Полноэкранные сцены разных карт пока не проверены. На примерах союзников есть белые ники без рамок; поиск рамок не определяет границы таких персонажей.

## Сбор

После установки из START_RU.md, в PowerShell из папки проекта:

```powershell
.\.venv\Scripts\python.exe tools/collect_overlay.py --live --every 2 --max 150
```

За 5 секунд переключись в полноэкранную игру на основном мониторе. F10 — остановка, F9 — пауза. При переключении в другое окно сохранение приостанавливается. Скрипт только читает экран и не управляет игрой. Если выбранный способ захвата не видит оверлей, рамки не обнаружатся.

По умолчанию сохраняются кадры с зелёной рамкой. Сохранение ограничено интервалом, точные дубликаты пропускаются.

Флаг --all-frames сохраняет кадры и без рамок. Для точечного сбора тиммейтов запусти сбор с --manual:

~~~powershell
.\.venv\Scripts\python.exe tools\collect_overlay.py --live --manual --max 50
~~~

Когда видна модель тиммейта, нажми X. В этом режиме снимаем только по X, включая кадры без рамок. F8 привязывает окно игры, F9 приостанавливает сбор, F10 завершает сессию.

Результат появляется в **overlay_review/отдельная_сессия/**, вне обучающего датасета:

- originals — оригиналы PNG;
- frame_….json — рамки, цвет, флаг обязательной проверки;
- possible_nameplate — найдены похожие на белые буквы элементы над рамкой. Это подсказка, не достоверный класс союзника и не распознавание текста.

Красные рамки записываются в JSON, если попали в кадр вместе с зелёными. Для сохранения и красных кадров без зелёных добавь `--keep-red`. Красные рамки НЕ экспортируются как обучающие цели: полностью скрытого персонажа на изображении нет. Если он частично виден, нужна ручная разметка.

## Приблизительное удаление рамок и метки YOLO

```powershell
.\.venv\Scripts\python.exe tools/collect_overlay.py --live --every 2 --max 150 --make-cleaned
```

Добавятся experimental_cleaned и erase_masks. Удаляется узкая полоса вокруг найденных контуров с приблизительным восстановлением пикселей. Это не оригинальный кадр без ВХ. Следы, ники и пропущенные рамки могут остаться; края персонажа могут исказиться. Исходники сохраняются. Восстановление линий не даёт доступа к тому, что скрыто стеной.

**Команда персонажа неизвестна.** Цвет означает видимость, а не команду. Ники служат только подсказкой: фон, перекрывающиеся надписи, дальние персонажи и разные масштабы дают ошибки. Игроки без рамок не размечаются этим инструментом, их нужно добавить вручную. Для улучшения распознавания союзников нужны полные кадры с включёнными рамками на союзниках.

Если ты вручную убедился, что ВСЕ зелёные рамки на выбранных кадрах относятся только к врагам, можно получить черновые YOLO-метки:

```powershell
.\.venv\Scripts\python.exe tools/collect_overlay.py --input "папка_с_исходными_PNG" --make-cleaned --class-id 0
```

Для кадров только с союзниками — `--class-id 1`. Этот параметр назначает один класс всем зелёным рамкам; для смешанной сцены так делать нельзя. Метки лежат отдельно в draft_labels и автоматически в обучение не попадают. Экспорт содержит нормированные координаты контура ВХ, который не обязательно совпадает с телом: исправь рамки в редакторе.

Перед переносом в dataset/raw/session_… проверь каждый кадр: добавь пропущенных видимых игроков, исправь класс и границы, удали ложные рамки. Не используй такие обработанные кадры как единственный источник обучения. Проверочная выборка должна содержать настоящие чистые кадры других игровых сессий. Автоматическая разбивка prepare_dataset.py не различает обработанные/чистые кадры: контролируй состав valid вручную перед обучением или держи экспериментальный датасет отдельно.

Надёжнее сначала разметить небольшой набор чистых кадров, обучить YOLO, затем исправлять её предварительную разметку. Этот инструмент — экспериментальный помощник, не замена проверки.

## Разметка врагов и тиммейтов по отдельности

Зелёная рамка означает, что игрок виден; сама по себе она не определяет команду. Красные рамки отмечают игроков за стеной и не используются как рамки видимых объектов YOLO.

Для кадров с обоими классами включи --all-frames и запускай сбор без `--class-id`:

```powershell
.\.venv\Scripts\python.exe tools\collect_overlay.py --live --every 1 --max 150 --all-frames
```

После сбора вручную разметь предложения:

```powershell
.\.venv\Scripts\python.exe tools\review_overlay_labels.py overlay_review\ИМЯ_СЕССИИ
```

В окне проверки `0` назначает enemy, `1` — teammate, `s` пропускает рамку, `u` отменяет предыдущий выбор, `q` завершает проверку. После предложений или на кадре без предложений клавиша `a` позволяет нарисовать рамку пропущенному видимому игроку; `0` или `1` назначает ему класс; Enter сохраняет кадр и метки в `dataset/raw/ИМЯ_СЕССИИ/`. Определи команду по игровому нику/индикатору, проверь все видимые тела и не включай скрытые цели.

Собери минимум две разные сессии, затем выполни `prepare_dataset.py`. Проверь примеры train/valid и только после этого запускай `train_yolo.py`.
